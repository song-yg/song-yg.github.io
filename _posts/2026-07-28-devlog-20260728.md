```python
    # --- 시간 예산 추적 시작 ---
    # time.monotonic()은 시스템 시각 변경(NTP 보정 등)에 영향 안 받는 경과 시간 측정용 시계라 이런 용도에 적합.
    collect_start = time.monotonic()
    budget_exceeded = False
    skipped_due_to_budget: list[str] = []
 
    def _over_budget() -> bool:
        return (time.monotonic() - collect_start) >= TIME_BUDGET_SECONDS
```

```python
    for batch_idx, batch in enumerate(batches):
        if _over_budget():
            remaining = [kw for b in batches[batch_idx:] for kw in b]
            skipped_due_to_budget.extend(remaining)
            budget_exceeded = True
            print(f"[gdelt] 🟡 주의 - 시간 예산({TIME_BUDGET_SECONDS // 3600}시간) 소진"
                  f" - 남은 배치 {len(batches) - batch_idx}개(키워드 {len(remaining)}개)는 이번 실행에서 건너뜀. 다음 실행에서 다시 시도됨.")
            break
```

## 오늘 한 것

## 1. GitHub Actions 실행 시간 관련
* **9시간 요청** → GitHub 호스팅 러너는 작업당 최대 **6시간(360분)이 인프라 하드 캡**이라 그 이상은 설정해도 무의미함을 확인, **360분으로 상향**(기존 240분)
* 우선순위 확인("일부 키워드 손실 감수하더라도 시간 안에 끝나는 게 중요") 후 → **GDELT 수집에 5시간 시간 예산(하드 데드라인) 신규 도입** — 예산 초과 시 남은 키워드는 "실패"가 아니라 "미시도"로 남기고 다음 단계로 즉시 넘어가도록 구현. mock 테스트로 조기 종료 동작 확인

<br>

### 2. 버그/이슈  분석
* **"LLM 지정 모델 실패 시 openrouter/free 자동 재시도" 기능 신규 구현** — relevance_filter.py(필터+재분류), issue_grouper.py(3차 그룹핑), llm_summarizer.py(요약) 3개 파일 전부 적용. 각 파일마다 mock으로 "지정 모델 실패 → free 자동 전환 → 성공" 시나리오 검증
* **LLM 후보 추가 폴백**: 모델 후보를 3개까지 추가하여 순차적으로 시도하도록 변경
* **GDELT ValueError**: 기존 실행 횟수 카운팅에서 실패 횟수 카운팅으로 변경
* **SKIP_KEYWORDS**: 제거하고 학습된 키워드에만 의존하도록 변경

<br>

### 3. 코드 변경 (총 4개 파일)
| 파일 | 변경 내용 |
|---|---|
| `issue_grouper.py` | LLM 폴백 체인 1단계→4단계 확장(1순위→2순위→3순위→openrouter/free) + 순위별 오류코드(IG-08~11) |
| `relevance_filter.py` | 동일 구조 적용 (RF-09~12) |
| `llm_summarizer.py` | 동일 구조 적용, `issue_grouper.py` 상수 재사용 (LS-02~05, 기존 LS-01 유지) |
| `gdelt_collector.py` | ① ValueError 카운팅을 "실행 횟수"→"발생 횟수" 기준으로 변경 ② `SKIP_KEYWORDS` 수동 목록 완전 제거(학습형 스킵으로 일원화) |

<br>
